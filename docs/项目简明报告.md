# Web 日志异常与审计程序：简明报告

## 这个项目是做什么的

网站每收到一次访问，通常会留下一条记录，叫作“日志”。它像网站的出入登记簿，写着访问时间、来源、访问了哪个页面，以及网站返回了什么结果。记录一多，人很难逐条查看。本项目把这些记录整理成一份报告，帮人找出值得检查的访问行为。

## 它怎样工作

1. **导入记录。** 在本机打开网页，选择访问日志文件，也可以先加载示例日志体验。
2. **整理数据。** 程序读取记录，统计访问量、错误比例和来源；格式错误的记录会单独列出，方便检查。
3. **提示线索。** 程序按预设规则寻找短时间内反复登录失败、大量错误请求、可疑访问路径等情况，并标出触发提示的原始记录。
4. **人工判断。** 使用者查看证据后，可以标记“确认”或“排除”，填写处理人和理由，保存处理过程。

例如，某个来源在一分钟内连续多次登录失败，程序会给出一条提示，并列出相关请求。它只是在提醒人检查；也可能是正常测试或用户误操作。

## 文件夹为什么这样分

| 位置 | 放什么 | 为什么单独放 |
| --- | --- | --- |
| `public/` | 网页的内容、样式和按钮交互 | 把用户看到的页面集中管理，改界面时容易找到。 |
| `docs/` | 项目说明、评价和交付文档 | 把“怎么用、为什么这样做”与程序代码分开，方便阅读。 |
| `data/` | 运行后生成的本地分析报告 | 把用户数据与程序分开；没有生成报告时，这个文件夹可以是空的。 |
| `.git/` | Git 保存的版本历史 | 方便查看和恢复代码改动，平时无需手动修改。 |

文件夹外的 `analyzer.js` 负责读日志和找线索，`server.js` 负责连接网页与分析程序并保存报告，`eval.js` 和 `analyzer.test.js` 负责验证结果。这样分工，界面、分析、保存和验证各有明确位置，修改一部分时更容易检查影响。

## 使用方法与适用范围

电脑安装 Node.js 18 或更新版本后，在项目目录运行 `npm start`，用浏览器打开 `http://127.0.0.1:3000`，点击“加载示例日志”即可体验。也可以导入自己的日志文件；单次最多 10 MB、100,000 行。分析报告保存在本机 `data/` 目录。

这是一个适合教学演示和小规模事后检查的单机工具。它不会实时监控网站，也不会自动封禁访问者。提示结果需要人结合实际情况核对；当前版本没有多人账号和加密存储，不适合直接当作正式的企业安全系统。
