# ADR-0001：采用单机离线、规则驱动的可追溯审计架构

- 状态：已采纳并实现
- 记录日期：2026-11-11（对现有实现的追溯记录，不冒充实施前决策日志）
- 关联：`README.md`、`docs/project.md`、`docs/api.md`、`tests/analyzer.test.js`、`tests/server.test.js`

## 背景与前置调研

项目要处理单份 Web 访问日志，识别候选异常并供人回查证据。课程演示需要无外部服务、可独立启动、可重复验证。先盘点已有输入格式和边界：JSONL 与 Common/Combined、旧日志缺失事件 ID、无效时间和重复 ID、60 秒聚合、人工处置。现有代码与测试表明这些问题可用确定性解析和规则处理；`docs/evaluation.md` 的八个合成会话只能检验教学样本，不能支持真实流量准确率结论。这是项目内部代码、契约和样本的追溯性调研，没有外部业务样本或性能基准研究。

## 候选方案

| 方案 | 可满足之处 | 当前代价或缺口 |
| --- | --- | --- |
| 本机 Node.js 服务、文件报告、确定性规则 | 无数据库和模型服务即可复现；每条告警能连接事件 ID | 单机同步处理；没有认证、并发写入控制和生产监控 |
| 实时采集加数据库 | 便于多人查询和大量历史检索 | 需要采集、权限、迁移与运维，超出本轮离线范围 |
| 在线模型分类 | 可探索非固定模式 | 需要标注数据、模型治理、成本与可解释性评估；现有八个合成会话不足以验证 |

## 决定与研究路线

采用第一种方案。按“解析与规范化 → 请求及滚动窗口规则 → 报告和事件证据 → 人工处置”分层。检测器不读取 `source_label`；坏行进入 `rejected`；有效事件和告警通过 `eventId` / `eventIds` 相连。报告保存数据集标识、规则版本和运行标识；旧报告不随代码更新重算。前端将原始文本作为文本展示。研究路线是先固定输入和规则契约，再用单元与接口测试验证边界，最后以固定会话做双版本实验；若转向真实业务，应先取得授权且独立标注的数据，再讨论阈值、存储和权限架构。

## 后果、验证与回退

好处是本机可演示、输出可复核、规则可版本化。限制是 JSON 文件明文保存在本机，报告写入缺少多用户并发控制，IP 不是人员身份，规则只覆盖预定义模式。通过 `npm test` 验证解析、窗口、证据和处置，通过 `npm run eval` 验证合成会话评价；两者都不能证明生产适用。若将来改用数据库或模型，先保留当前报告格式与历史代码版本，新增迁移和对照测试，不直接改写旧结论。
