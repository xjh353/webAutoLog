# ADR-0002：获批压测清单仅作为候选规则的外部上下文

- 状态：已采纳为实验候选；网页默认版仍为 P2-R1
- 记录日期：2026-11-11（对现有实验的追溯记录）
- 关联：`fixtures/experiment-plan.json`、`fixtures/approved-load.json`、`docs/experiment.md`、`docs/evaluation.md`

> **这份文档回答**：为什么获批压测清单只作为候选规则 P2-R2 的外部上下文，而不直接影响默认版——含调研依据、方案决定与风险。

## 问题与调研依据

固定阈值会将正常的高频压测报为候选异常。项目先查现有规则卡、批准清单、合成样本和逐会话结果：P2-R1 在测试分区四个会话中出现一个误报；该压测会话有独立的服务与会话批准记录。不能从日志的 IP、路径或 `source_label` 自行推断“已批准”。这项调研只覆盖仓库内构造情境，没有业务方实际批准流程的证据。

## 方案与决定

| 方案 | 判断 |
| --- | --- |
| 降低或取消全局高频规则 | 可能连未获批的集中请求也漏掉，改变因素过多 |
| 从日志文字或标签推断批准 | 来源不可信，评价标签泄漏到规则 |
| 由调用方提供服务＋会话 ID 的独立批准清单 | 只改变指定会话的高频告警处理，能留下抑制证据 |

采用第三种作为 P2-R2 实验候选。匹配时只抑制高频请求规则，其他规则不变；`suppressed` 保存理由和事件 ID。按预先写入 `fixtures/experiment-plan.json` 的同输入、同窗口、同统计单位和质量门槛，与 P2-R1 比较。当前测试分区的 FP 从 1 到 0、FN 保持 0，但每个分区只有四个构造会话，所以决定仅是“值得用独立真实样本继续验证”，没有切换网页默认策略。

## 风险与后续

若清单来源错误、过期或被滥用，真实异常可能被抑制。真实应用须定义批准人、有效期、服务/会话作用域和撤销流程，并测量人工复核成本。回退方式是保持或恢复 P2-R1；历史报告以各自 `ruleVersion` 保存，不能因回退而改写。
