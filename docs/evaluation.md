# 合成数据评价记录

运行 `npm run eval`。脚本固定四个完整会话：正常浏览、失败登录、404 探测、已批准的高频压测。标签来自构造情境，不代表真实互联网真值。`source_label` 虽在输入中，但分析器不读取它来决定告警。

统计单位是**会话**，同一会话的所有事件留在同一组。预测规则为会话中存在至少一条候选告警。当前构造集仅用于演示计数与误报取舍，没有划分可用于调参的独立训练集，因此不能据此宣称真实准确率。

| 策略 | TP | FP | FN | TN | Precision | Recall | FPR |
|---|---:|---:|---:|---:|---:|---:|---:|
| A：固定规则 | 2 | 1 | 0 | 1 | 66.7% | 100% | 50% |
| B：对已批准压测过滤高频规则 | 2 | 0 | 0 | 2 | 100% | 100% | 0% |

B 只改变一个因素：外部批准的压测上下文，其他事件、规则和分母保持一致。该上下文目前只在评价脚本中用于对照，不会自动放行生产日志。四个会话太少，B 的结果仅说明这一个构造反例被正确识别；它也可能在别的数据上漏报。人工复核量可按两策略的候选会话数比较：A 为 3，B 为 2。两策略均未使用模型调用，AI 运行成本为零。

计算方式：`Precision = TP/(TP+FP)`，`Recall = TP/(TP+FN)`，`FPR = FP/(FP+TN)`。脚本输出逐会话预测，便于查找误判，避免只报告单个总分。
