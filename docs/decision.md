## 03 决定

按预设的 `decisionRule`（质量门槛通过且测试分区 FP 减少 ⇒ 值得继续验证），本轮决定：

1. **保留原办法**：网页默认策略仍是 P2-R1，`fixtures/approved-load.json` 不参与日常导入，教学候选不直接用于生产判断。
2. **继续检查候选**：P2-R2 列为「值得用独立真实样本继续验证」，需要经授权且标注完整的独立会话、人工复核时间测量，以及批准清单来源与更新责任，才能进入下一轮判断。
3. **不采用、不部署、不宣称准确率提升**，也不把这个 4 会话分区的结果写成泛化能力。

关于课件「材料不全就暂不选择」：本轮约定事先把判断限定在「是否值得继续验证」这一级，质量门槛与 FP 证据都齐备，所以可以给出上述决定；若要进一步做「采用 / 更换默认策略」的选择，人工与清单成本仍属未知，此时正确写法是**暂不选择**，不能越级下结论。

## 04 边界

### 还有什么没测

- 真实业务流量准确率、泛化能力、速度优势；两侧仍是相似行为类型，每个分区只有 4 个构造会话。
- 人工复核 3 → 2 个待复核会话是否真的节省分钟数；批准清单的准备、维护与撤销成本。
- 伙伴独立复现与差异处理、人工签署（`docs/Tasks.md` T-07），以及真实业务阈值校准（T-08）——这两项需要外部参与者，仓库如实标注为待执行，本文件不替伙伴填写结论。
- 失败与超时轮次的保留机制：本次 0 次，尚未遇到真实失败场景。

### 什么变化会让我们重新比较

下列任一情形出现，就按同一约定重新跑一次比较，而不是沿用本结论：

1. **批准信息可靠性变化**：清单缺少批准人、有效期、作用域或撤销流程；清单过期、被滥用，或覆盖到非压测会话。
2. **质量门槛失效**：出现清单外的高频流量，或被抑制会话中出现目标异常（FN > 0），或告警 `event_id` 回查失败。
3. **数据变化**：取得经授权的独立真实会话，或开发／测试分区结果不再一致，或输入格式与会话分布改变。
4. **复现出现差异**：伙伴独立运行得到不同结论（FP 未降、FN 增加、回查失败、出现失败／超时轮次）。
5. **代码或约定变化**：解析器、60 秒窗口、其他阈值、规则版本或 `scripts/eval.js` 改变（以 `sourceHashes` 核对）。
6. **代价结构变化**：人工复核时间或清单维护成本被实测出来，且明显改变「收益 vs 代价」的判断。

重新比较时：新建 `data/experiments/<新运行号>/` 与新的证据目录，**不改写** `evidence/run-2026-11-12/` 的任何数值；若约定本身需要调整，必须先写进 `fixtures/experiment-plan.json` 再运行，不能在看到结果后换尺子；失败与超时轮次照原样保留。回退方式始终是保持或恢复 P2-R1。
