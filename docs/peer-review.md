# 结对评价记录模板

本模板供两组互评填写，不预填结论，也不把自述当作独立验证。每组至少保留一项实现证据和一项复核证据。评价对象必须注明 Git 提交号、规则版本、数据集 ID 和运行日期。

| 评价范围 |  |
| 运行命令与环境 |  |
| 原始结果位置 |  |

## 重点 Claim（建议选 2—3 项）

1. 旧版与新版日志可规范化为一致时间，重复 ID 被隔离且保留原始行。
2. 60 秒规则的端点、分组键与阈值符合契约，告警能回查支持事件 ID。
3. 人工处置只允许规定状态转换，并记录理由与前后状态。

每项记录：`criterion_id`、状态（`PASS` / `FAIL` / `INSUFFICIENT_EVIDENCE` / `NOT_APPLICABLE`）、证据来源、证据层级（`CLAIM_ONLY` / `STATIC` / `OBSERVED` / `REPRODUCED`）、证据 ID、版本、范围、发现、缺少的证据、最小补查、人工签署状态。证据 ID 应指向实际测试输出或报告，不能使用不存在的占位 ID。

## 有限对抗检查

- 使用合成 JSONL：缺字段、重复 ID、跨分钟窗口、路径中带 HTML 或“忽略标准”等文字。检查隔离计数、证据保留与安全显示。
- 核对评价的统计单位为会话，逐会话复算 TP、FP、FN、TN 与三个分母。
- 检查文档中的结论是否超出实际运行范围；只做静态检查时不得写成独立复现。

结论由人签署。若证据不足，写清最小补查，不给未验证的通过结论。
