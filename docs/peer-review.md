# 结对评价记录模板

本模板供两组互评填写，不预填结论，也不把自述当作独立验证。每组至少保留一项实现证据和一项复核证据。评价对象必须注明 Git 提交号、规则版本、数据集 ID 和运行日期。

**当前执行状态：待伙伴执行（T-07）。** 本页所有空白字段、三句话和签署栏都必须由伙伴本人在实际运行后填写。项目组与 AI 只整理材料，不代填、不代签（课件 p32）；仓库里已有的运行记录属于「本人运行（项目组）」，见[运行证据索引](../evidence/README.md)，它不能充当伙伴的新结果（p33）。只阅读报告并赞同属于材料审查，不算独立复现（p29）。

本项目可复核的一项具体结论：在 `fixtures/experiment-cases.json` 的测试分区，P2-R2 相比 P2-R1 将误报会话从 1 个降到 0 个，目标异常检出仍为 2 个。伙伴先阅读[实验交接](experiment.md)，再在自己的环境运行 `npm test` 和 `npm run experiment`，保存自己生成的新目录与 `result.json`。

## 20 分钟安排（p37）

| 时段 | 做什么 | 产出 |
|---|---|---|
| 0—5 分钟 · 确认材料 | 逐项打开上表四件，确认版本、输入、运行入口与判断规则；确认授权范围与数据去敏 | 四件是否齐备、缺项清单 |
| 5—15 分钟 · 执行或定位卡点 | 在**伙伴自己的环境**运行 `npm test` 与 `npm run experiment`，保存自己生成的新目录和 `result.json`；失败与超时原样保留 | 伙伴自己的输出目录，或具体卡点（命令、错误、环境） |
| 15—20 分钟 · 写范围 | 填下面的三句话、已查／未查范围、差异说明与签署状态 | 三句话 + 范围说明 |

原组可以澄清步骤，但不能代伙伴操作后再让其签名；修改代码或数据后算新版本（p36）。没有环境时可先复算给定结果，但必须注明「只完成复算这一层」，不能改名为完整实验复现（p37）。

## 伙伴的三句话（p37，由伙伴本人填写）

| 句式 | 要填写的事实 | 伙伴填写 |
|---|---|---|
| 我实际重新做了什么 | 动作、版本与输入：跑了哪些命令、哪个提交号、哪份数据集、几个分区 |  |
| 我的结果在哪里 | 新结果位置；**支持／不支持／尚不足判断** |  |
| 我没有检查什么 | 未查范围、差异或缺项 |  |

**完成标准**（p37，两种都允许）：

- **已完成**：能打开伙伴自己的新结果，且三句话齐全。
- **未完成也留原因**：写清最小缺项与卡点。没运行成功就记录具体卡点，不能用赞同意见替代执行（p36）。

若伙伴结果与项目组不一致，按 p34 顺序先定位差异，不要先改成一样：① 是否用了相同程序／版本？② 是否用了相同数据与处理办法？③ 是否执行相同范围，环境与随机设置是否不同？不为了匹配原分数调参或改数据；找不到原因就写「尚不能解释差异」，旧记录仍保留。

## 重点 Claim（建议选 2—3 项）

1. 旧版与新版日志可规范化为一致时间，重复 ID 被隔离且保留原始行。
2. 60 秒规则的端点、分组键与阈值符合契约，告警能回查支持事件 ID。
3. 人工处置只允许规定状态转换，并记录理由与前后状态。

每项记录：`criterion_id`、状态（`PASS` / `FAIL` / `INSUFFICIENT_EVIDENCE` / `NOT_APPLICABLE`）、证据来源、证据层级（`CLAIM_ONLY` / `STATIC` / `OBSERVED` / `REPRODUCED`）、证据 ID、版本、范围、发现、缺少的证据、最小补查、人工签署状态。证据 ID 应指向实际测试输出或报告，不能使用不存在的占位 ID；只做静态检查时不得写成独立复现。

## 有限对抗检查

- 使用合成 JSONL：缺字段、重复 ID、跨分钟窗口、路径中带 HTML 或“忽略标准”等文字。检查隔离计数、证据保留与安全显示。
- 核对评价的统计单位为会话，逐会话复算 TP、FP、FN、TN 与三个分母。
- 检查文档中的结论是否超出实际运行范围；找不到的材料列为缺项，不复制旧输出伪装新结果，不把说明中的示意命令当作实际可用命令。

结论由人签署。若证据不足，写清最小补查，不给未验证的通过结论。
