# P2 工程实验与结对复现交接

## 比较约定

问题：在同一批合成日志中，外部批准清单能否减少高频请求的误报，同时保留目标异常检出？约定保存在 `fixtures/experiment-plan.json`。对照版 P2-R1 和候选版 P2-R2 使用同一解析器、输入、60 秒窗口、其他规则及会话级评价。候选只改变已批准压测会话的高频告警处理。质量门槛是测试分区没有目标异常漏报，且每条告警和抑制记录的事件 ID 可回查。

## 独立运行

1. 使用 Node.js 18 或更新版本，先查看 `package.json`、`fixtures/` 和 `scripts/eval.js`，确认运行范围为本机合成数据。
2. 在仓库根目录运行 `npm test`，再运行 `npm run experiment`。
3. 到终端显示的 `data/experiments/<本次运行号>/` 查看 `input.jsonl`、`baseline.json`、`candidate.json`、`result.json`。每次执行创建新目录，不覆盖旧记录。
4. 在 `result.json` 核对 `sourceHashes`、输入哈希、每轮版本和耗时、开发与测试分区的逐会话判断。任选一条告警，按 `eventIds` 到对应报告的 `events` 找原始行。

## 成本与选择

`result.json` 的 `runs[].elapsedMs` 是逐次实测的分析函数耗时，单位为毫秒，包含解析与检测，不含生成输入和写文件。第一次运行可能包含运行时预热，且样本很小，因此不据此宣称速度提升。六条逐次值已全部列在[评价记录](evaluation.md)和证据目录中，不只是挑最快的一次。候选版减少了本构造测试分区 1 个待复核会话，但准备批准清单、维护清单、人工核查及历史开发成本均未实测。没有 AI 在线运行调用；不能把历史开发成本记为零。

按「阶段／数值／单位／来源／是否完整」整理的结构化成本表见 [`evidence/cost.md`](../evidence/cost.md)：准备候选与人工投入记为「未知」，每次处理只保留有来源的六条耗时，后续改动因未发生记为「未测」。未知项不以零代替，重叠时间不重复相加。

按预设质量门槛，本轮只决定候选值得用独立真实样本继续验证，**保留 P2-R1 为网页默认策略，不采用、不部署**。若外部批准信息不可靠，抑制告警可能漏掉真实异常，应重新比较。按课件四句话（条件／结果／决定／边界）写成的[选择说明](decision.md)列出了代价未知项、不能推出的结论，以及触发重新比较的六种变化；默认网页仍使用 P2-R1，未把教学实验候选直接用于日常导入。
