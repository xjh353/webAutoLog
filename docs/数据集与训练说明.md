# 数据集与训练/微调说明

> **这份文档回答**：实验用的数据集是什么、怎么来的，以及本项目有没有训练/微调、为什么——对应课程表单「完成情况」中的「其他」一项。结论先行：数据集是仓库内固定合成情境，可确定性重建；本项目是规则驱动程序，**没有训练/微调环节**，这是架构范围决定，不是遗漏。

---

## 一、数据集说明

### 1. 数据集从哪来

实验数据不是采集或下载的真实日志，而是由仓库内两个固定文件**确定性生成**的教学合成情境：

| 文件 | 作用 |
| --- | --- |
| [`fixtures/experiment-cases.json`](../fixtures/experiment-cases.json) | 定义 8 个会话的构成：分区、标签、条数、路由、状态码 |
| [`fixtures/approved-load.json`](../fixtures/approved-load.json) | P2-R2 候选用的外部批准清单，记录哪些服务＋会话属于获批压测 |
| [`fixtures/experiment-plan.json`](../fixtures/experiment-plan.json) | 事先写死的五句约定，定义数据与共同条件 |
| [`scripts/eval.js`](../scripts/eval.js) | 读取以上文件、生成输入、回放两版规则并计分 |

真实日志和任何业务数据都**不进入仓库**；标签只来自合成情境定义，不来自对真实流量的标注。

### 2. 生成规则（确定性，可复算）

`scripts/eval.js` 的 `makeInput()` 按下式展开每个会话：

- 事件 ID：`{会话id}-{序号}`，如 `test-login-0`。
- 事件时间：固定基点 `2026-11-04T02:00:00Z`，按会话序号每会话递进 120 秒、按记录序号每条递进 1 秒——因此同一会话的事件落在滚动窗口内。
- 服务：固定为 `teaching`。
- 会话 ID：取情境定义的 `id`。
- 路由与状态码：取情境定义；`varyRoute` 为真时路由追加序号，形成探测不同路径的样本。
- 延迟：固定 15 毫秒。

同样的文件在任何机器上运行都生成**逐字节相同**的输入；输入 sha256 与数据集 ID 记录在[运行证据](../evidence/README.md)中，可核对。

### 3. 规模与分区

共 **8 个完整会话、94 条记录**，开发分区与测试分区各 4 个会话：

| 分区 | 会话 | 标签 | 条数 | 情境 |
| --- | --- | --- | ---: | --- |
| development | dev-normal | normal | 4 | 正常浏览 |
| development | dev-login | anomaly | 5 | 登录失败 |
| development | dev-scan | anomaly | 8 | 404 探测 |
| development | dev-load | normal（获批压测） | 30 | 高频请求 |
| test | test-normal | normal | 4 | 正常浏览 |
| test | test-login | anomaly | 5 | 登录失败 |
| test | test-scan | anomaly | 8 | 404 探测 |
| test | test-load | normal（获批压测） | 30 | 高频请求 |

### 4. 标签的用途与隔离（关键边界）

`label` 只存在于 `experiment-cases.json`，**不会写入传给分析器的日志行**：`makeInput()` 生成的 JSONL 不含 `label`／`source_label` 字段。计分时 `score()` 才用标签判断 TP/FP/FN/TN。因此检测器不可能读到"答案"，评价标签没有泄漏到规则判断。这是[项目设计](project.md)与[规则卡](rules.md)共同约束的边界。

统计单位是**完整会话**（会话内有至少一条候选告警即预测为异常），不是日志行数；分母、口径与结果见[评价记录](evaluation.md)。

### 5. 批准清单的来源

P2-R2 依赖的批准信息来自独立文件 `fixtures/approved-load.json`，标明来源为「教学合成情境中的外部批准记录」，只列出 `service=teaching` 下 `dev-load`、`test-load` 两个会话。**批准关系不从日志的 IP、路径、状态码或标签推断**——这是[ADR-0002](adr/0002-approved-load-experiment.md)明确记下的决定，避免把评价答案泄漏给规则，也避免凭文字就认定"已批准"。真实业务中的批准人、有效期与撤销流程尚未定义，属于待外部参与者的边界。

### 6. 怎么重新生成

```bash
npm test              # 15/15 验证解析、窗口、证据与实验约定
npm run eval          # 回放合成数据，终端输出逐会话评价
npm run experiment    # 双版各 3 轮，保存输入、报告与逐次记录到 data/experiments/
```

`npm run experiment` 的输出目录含 `input.jsonl`、`baseline.json`、`candidate.json`、`result.json`；`data/` 按[项目级 Harness](../AGENTS.md)不纳入 Git。已固化的一次真实运行原始记录在[运行证据](../evidence/README.md)，提交号、环境与文件哈希在[补记元数据](../evidence/run-2026-11-12/manifest.json)。

### 7. 数据集边界

- 8 个会话、相似行为类型，是**教学构造样本**，只能展示计算过程与规则差异，不能作为真实场景准确率、泛化能力或速度优势的证据。
- 阈值（登录失败 5 次、4xx 8 次、5xx 5 次、总请求 30 次）是课程演示值，未按真实业务基线校准；真实数据校准（T-08）需授权且标注完整的独立会话，尚未启动。

## 二、训练/微调说明

### 1. 结论

**本项目没有训练或微调环节。** 系统是确定性规则驱动：日志按固定解析规则规范化，按固定阈值和 60 秒窗口匹配，输出带事件 ID 的候选告警。全流程没有模型权重、没有参数学习、没有反向传播、没有需要训练的数据集划分。

### 2. 为什么这样设计（依据）

[ADR-0001](adr/0001-offline-audit-architecture.md) 记录了架构取舍：在「本机 Node.js＋文件报告＋确定性规则」「实时采集加数据库」「在线模型分类」三个候选中，选了第一种，因为课程演示需要无外部服务、可独立启动、可重复验证，而每条告警都要能连接到事件 ID。在线模型分类被列为候选但**未采用**，原因是它需要标注数据、模型治理、成本与可解释性评估，而当时只有 8 个合成会话，不足以验证。这一决定同时写在[Global](Global.md)的范围与责任里：当前交付是单机、离线、教学规模的候选异常审计，不承担实时采集或生产级能力。

因此「没有训练/微调」是**范围决定**，不是做漏了；把它写成"训练/微调说明"的正确方式，就是说明为什么不需要。

### 3. 容易混淆的几点

- **P2-R1 / P2-R2 不是两个模型**，而是同一分析器的两个规则策略（通过 `strategy` 参数选择）。切换它们是规则版本切换，不是模型微调；差异只在"是否对获批会话抑制高频告警"这一处，见[规则卡](rules.md)与[ADR-0002](adr/0002-approved-load-experiment.md)。
- **"阈值未校准"不等于"训练过"**。本项目从未根据数据自动调整阈值；阈值是手写常量。若要按真实业务校准，属于后续改动（成本记「未测」），也不是微调模型。
- **开发/测试分区不是机器学习的训练/验证/测试划分**。它只是把 8 个合成会话分成两组：开发分区用于观察、测试分区用于按事先写死的约定做一次比较。没有用开发分区去"学习"任何参数再应用到测试分区。
- **没有接入在线 LLM**。[项目设计](project.md)明确写明：AI 辅助实现代码和测试，但程序运行时不调用在线模型；日志中的诱导文字始终作为数据处理。

### 4. 未做与边界

- 未做任何模型训练、微调、提示词工程或 embedding；未采集训练语料；未产生模型权重或检查点。
- 未做标注数据的真实业务采集；标签仅来自合成情境。
- 若将来引入模型，须先按 `AGENTS.md` 记入 ADR、取得授权与标注完整的独立数据，并重新设计可解释性与回退方案，不能把当前 8 会话结果直接外推。
