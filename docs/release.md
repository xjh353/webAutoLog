# 交付与复核

## 从干净环境恢复

要求 Node.js 18 或更高版本。克隆仓库后运行 `npm test`、`npm run eval`、`npm start`，浏览器打开 `http://127.0.0.1:3000`，点击「加载示例日志」。项目没有第三方运行依赖。真实报告在本机 `data/`，不纳入 Git；换设备时需要单独安全迁移该目录。

## 版本与变更

当前规则 `P2-R1`，契约详见 [项目设计](project.md)。P2-CH01 的输入兼容点：旧 Common/Combined 日志仍可导入，JSONL 可用 `request_id`，时间统一为 UTC，重复 ID 隔离。回归测试检查旧新版同一时间点的规范化结果。

更新规则时必须提升规则版本、保留旧代码版本，并用同一评价数据重跑。已有报告继续显示生成时的 `ruleVersion`、告警和处置历史。当前程序没有一键选择旧规则重跑的界面；可以检出对应 Git 版本后用同一输入重新分析。

## 人工复核边界

检测结果是候选异常。`CONFIRMED` 表示操作人基于证据完成确认，`DISMISSED` 表示操作人说明排除理由；当前本地版没有用户身份验证。不得把 IP 直接映射为个人，不能用这份合成数据评价宣称真实误报率。导出报告可能包含原始路径、会话标识和其他敏感字段，分享前应按团队要求脱敏。
